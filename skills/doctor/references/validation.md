# Validation and migration scope

The YAML runner has isolated acceptance coverage for real red → correction → green, definition/script/adapter
hash invalidation, explicit confirmation, duplicate and invalid YAML, ambiguous executors, references, selection,
partial capabilities, keep/success, timeouts, missing infrastructure, untracked files, rename paths and uncovered files.
The generic doctor regression suite remains separate.

A fresh baseline and a fresh skill-enabled native agent performed the same greeting correction, sequentially.
The skill-enabled session wrote its contract before code, confirmed two relevant observed failures and finished
`--all` with two PASS results including a code-consumer journey. The baseline implemented and checked the function
without a contract. This is one small local comparison, not a general effectiveness claim. Raw sessions, outputs
and proofs remain in the user's state directory. An unconfigured automated agent adapter still reports PEND.

The local-agent migration preserves the legacy entrypoint and compares ten safe checks through both compatibility
paths. The strict contract does not inherit legacy green: nine successful fast observations are PEND until matching
red proof is reviewed. Role setup and session-start JSON were tested in an isolated agent home. Live desktop
journeys and model adoption of the voice are separate from checking generated settings. A real installed-plugin
Claude session emitted startup hooks and reported the configured shared output style, but its subscription weekly
limit prevented the behavioral response. Voice behavior remains pending; no paid API fallback was used.

The external application's existing doctor and the shadow adapter agreed on ten gate assertions. The shadow
invokes the original assertions, so this is adapter compatibility, not an independent rewrite. All ten strict
verdicts remain PEND without real red proofs. Its required-check list and CI were unchanged; database and external
service checks were excluded from this local comparison. No machine paths, raw client data or private transcripts
are published here.

Self-learning produced a proposal citing a successful skill load and a subsequent real user correction. It did not
apply that proposal. Fixtures verify explicit application, stale/tampered evidence rejection, and rollback when the
doctor fails, remains pending, times out or is unavailable.

The isolated local marketplace installed plugin version 0.105.0 through the real Claude installer. Its cached
YAML interpreter reran the fresh-session fixture with both confirmed checks PASS. This isolated install does not
replace the active production marketplace; activation from its main branch follows PR merge.
